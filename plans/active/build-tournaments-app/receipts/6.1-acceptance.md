## One real-world issue surfaced

The candidate `src` values originally pointed at `/tmp/logo-a.png` etc. — absolute filesystem paths. The Tournaments server only serves `public/` as static, so the browser interpreted them as URL paths and got 404s. Fix applied for this test: copy the three logos into `<root>/public/acceptance-logos/` and rewrite the `src` fields to `/acceptance-logos/<name>.png`.

This is a known gap in the skill: when candidates point at paths outside the project tree, the user must either copy the files into `public/` or the skill should do that itself. The SKILL.md already flags this in the "Build the tournament JSON" section ("for arbitrary absolute paths the user may need to copy the file into the app's serving root first — surface this if the path is outside the project"), but the script doesn't yet automate the copy. This is suitable follow-up work, not a blocker for accepting the kit.
